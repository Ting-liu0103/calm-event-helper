# AGENTS.md — RAG 入門 LLM Wiki 工作規格

## 目標
從 `raw/` 的 5 份可追溯來源摘要建立繁體中文 RAG 教學 Wiki，再**只依據 Wiki 與對應證據卡**製作 8–15 張 HTML 簡報，讓初學者理解 RAG 流程。

## 讀者與語言
大學初學者；繁體中文；第一次出現的術語同時給中文與英文。每張簡報只講一個主要概念，避免大段文字。

## 檔案角色
- `raw/S*.md`：外部資料的來源紀錄與改寫摘要，標明非原文全文。
- `wiki/index.md`、`wiki/concepts/*.md`、`wiki/log.md`：可查詢的 Wiki 知識與 ingest 紀錄。
- `cards/*.md`：一張卡只使用對應來源；不得混入其他來源。
- `outline.md`：頁面教學順序與來源對應。
- `drafts/slides.md`：逐頁文案，只能使用大綱與證據卡。
- `slides/index.html`：只渲染通過檢查的文案；渲染時不改動事實。
- `report.md`：檢查結果、修正、剩餘風險。

## Ingest 規則
1. 讀 `raw/` 來源紀錄，檢查 URL、標題、類型與主張。
2. 一次整理 1–2 份來源，更新 Wiki 概念、索引與 log。
3. 每個重要主張標 [S1]–[S5]；不可補寫來源沒有的數字或結論。
4. 若來源衝突，記錄差異；不能解決則標記待確認。
5. 禁止加入個資、未授權私有資料、密碼或 API key。

## Loop / Graph 規則
- Graph 節點：資料檢索 → 覆蓋率關卡 → 證據卡 → 大綱 → 人工確認 → 逐頁稿 → 忠實度檢查 → HTML 渲染 → 渲染檢查 → 交件。
- 來源不足：退回檢索或停下，不用模型常識硬湊。
- 逐頁稿不忠實：只退回錯誤頁，最多 2 次局部修正。
- HTML 操作／版面失敗：只退回渲染節點，最多 3 次。
- 檢查必須有可重現指令、通過條件與結果，不得只寫「已檢查」。
- AI 內容審查應由**新的獨立對話**僅提供成品與來源，避免自己審自己；未執行不得宣稱已完成。

## 完成標準
至少 5 份 ingest 來源；每份有來源頁與 Wiki 概念；8–15 張投影片；每張有可追溯出處或明確標為教學自製示例；互動按鈕存在；程式檢查通過；人工/獨立 AI 審查狀態清楚記錄。

## 工具與版本
使用 Git 保存每次改動，執行 `python3 scripts/lint.py`。只維護這份 AGENTS.md 作為主要工作規則。
