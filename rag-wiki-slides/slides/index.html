模型主要依訓練過程形成的內部知識作答。對特定私有文件或更新內容，可能沒有足夠資訊。

加入 RAG

04 / DEFINITION

RAG：檢索增強生成（Retrieval-Augmented Generation）

使用者提問
→
檢索（Retrieval）
找相關資料
→
生成（Generation）
根據資料回答

像是「開卷作答」：先查資料再寫答案；但開卷不保證答對，還要檢查有沒有正確使用資料。

來源：Wiki [S1] [S5]

05 / EMBEDDING

嵌入向量（Embedding）：把文字轉成數值

使用者的問題

「貓咪為什麼不喝水？」

Query embedding → 數值向量

知識庫文件

「改善貓咪飲水意願的方法」

Document embedding → 數值向量

向量搜尋可以找到「用字不同但語意接近」的內容；相似度不等於真實性。

來源：Wiki [S2] [S4] · 例句為教學示意

06 / INDEX

FAISS：向量相似搜尋工具

文件
→
切分文件（Chunking）
→
Embedding
→
FAISS 向量索引

Chunk 太大

多個主題混在一起，可能降低檢索精準度。

Chunk 太小

缺乏必要上下文，回答時可能失去原意。

來源：Wiki [S3]；chunk 取捨為實作設計考量

08 / EXAMPLE

以校園活動指南為例

問題：「活動遇到下雨，總召要先做什麼？」

檢索器（Retriever）：找出「雨備流程」「場地變更」「通知窗口」等相關段落。

生成器（Generator）：根據檢索段落整理步驟，並標示來源；這是有根據的回答（Grounded Answer）的教學示意。

檢查：是否有寫出文件沒有提到的校方規定？如果有，應刪除或標記待確認。

教學假設案例；非真實 Wiki 查詢結果

09 / LIMITATIONS

RAG ≠ 自動消除幻覺

檢索錯

找到不相關的文件。

資料不足

知識庫沒有答案。

生成錯

模型誤解文件或加上無根據內容。

所以要分開檢查：找得對不對、答得有沒有根據。

來源：Wiki [S1] [S5]；評估方式為教學延伸

12 / TAKEAWAYS

帶走三個重點

① 先找資料

Retriever 取得可能相關的外部資訊。

② 再整理回答

Generator 使用取得的內容產生自然語言答案。

③ 最後要驗證

檢查來源相關性、答案忠實性與無答案情況。
